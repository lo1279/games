## 全局 UI 美化 · 阶段 2：骨架统一（index.html 重构）

### 核心约束：display 的管辖权不可迁移（本阶段最重要的发现）
- `main.js` 有 **75 处 `.style.display`** 直接接管元素显隐。逐容器统计接管次数：`tileActionModal` 8 · `sandboxCustomModal` 4 · `gachaShowcase` 3 · `battleDetailModal` 2 · `gachaPoolPreviewModal` 2 · `viewOwnedGenerals/viewTacticsUpgrade/generalsActionBar` 各 2 · `campaignsContainer/trialsContainer/sandboxContainer` 各 1 · `rechargeModal` 2。
- **铁律**：凡 JS 会写 display 的元素，初始 display 必须留在内联 style 上。迁移会导致「弹窗打不开」或「隐藏元素冒出来」。因此骨架层 CSS **刻意不提供任何 display 声明**。
- 反例（可安全迁移）：`hudResWood/Iron/Stone/Grain`、`btnNavTabCity` —— JS 完全不碰，纯 HTML 状态。
- `tileModalBody` / `sandboxModalBody` 等只被写 `innerHTML`+`querySelector`，**不碰 display**，可安全转 `.stack` / `.modal-body--scroll`。

### 🔴 本阶段最严重的一次 bug（必须记住）
**62 处类名被写成裸属性而非 `class="..."`**，形如 `<span val-ok>` / `<div card-note>` —— HTML 解析器当作未知属性**完全忽略**，导致阶段 3 最核心的语义色收敛**一度全部没生效**。
- **根因**：批量替换脚本的 `merge_class()` 在「标签已有 class」与「标签无 class」两种情况下的分支处理有误。
- **发现方式**：验证脚本统计「类被引用次数」时数值与预期不符（`card-note--tight` 恒为 0）→ 打印原始字节上下文才看出是裸属性。
- **修复**：全量 54 处（`val-*` 49 + `card-micro` 5），另 8 处 `card-note` 单独修。
- **教训（关键）**：
  1. 验证时**不能只看计数**，计数 >0 也可能是错的形态。必须打印**原始字节上下文**（`repr(js[i-110:i+40])`）肉眼确认。
  2. 检测裸属性的可靠正则：遍历标签 `<[a-zA-Z][\w-]*[^>]*>`，跳过含 `class="...类名..."` 的，再查是否有独立出现的类名 token。
  3. 注意 `<span class=` 本身就是**合法 HTML**（标签名与属性间有空格），不要误报为「裸 class 属性」。

### 其他错误与教训
- **`.card` 基类层自建后被我亲手删除**：初版建了 `.card` + 6 尺寸档 + 6 色调变体共 27 个类，实测发现 (a) 6 类目标卡片在源码中共 8 处出现但**零处挂上 `.card`**（`.card` 的 67 次"引用"全是 JS 局部变量名 `const card = document.createElement(...)`，不是 class）；(b) `.card` 含 `display:flex`，**违反阶段 2 确立的铁律**（凡 JS 会写 `.style.display` 的元素，样式必须留内联）。
  → **教训**：不要为「看起来完整」而建未被接线的抽象层。卡片收敛靠统一令牌取值，不靠统一类名。
- **抽象类必须过Rule of Three 门槛**：实测 muted 小字号在 main.js 有 41 处，但分散成 **29 种写法**、多数只出现 1-2 次 → 只抽了达标形态，其余保留内联。同理 `padding:2px 8px`(18) / `border-radius:3px`(36) 等属 badge/chip 类，横竖内边距与圆角强绑定，抽类收益低于成本。
- **`.card-row` 引入 `gap` 造成隐性回归**：接线 `space-between`(36 处) 时若类里带 `gap:8px`，会让原本无 gap 的 **23 处**凭空多出间隙 → 拆分为 `.card-row--split`（只做两端对齐+垂直居中，不声明 gap/flex-wrap）+ `.card-row--wrap`（显式换行）。

### 关键技术发现
1. **Windows 实测字体命中**：查 `C:/Windows/Fonts/` 确认有 `simsun.ttc` / `simkai.ttf` / `simhei.ttf` / `georgia.ttf` / `times.ttf`。`--font-serif` 栈里 `"Songti SC"`（macOS）与`"Noto Serif SC"`（未安装）**都会跳过**，Windows 实际落到 **`SimSun`**。
2. **SimSun 字面偏小、笔画细密**，直接用于 18-22px 标题会单薄 → 配 `fw-bold` + `0.02em` 字距 + 极淡`text-shadow: 0 1px 2px rgba(0,0,0,.35)`（强度控制在几乎不可察觉）。**此补偿值无浏览器验证，可能需微调**。
3. **`.game-title` 例外**：该类用 `background-clip: text` + `-webkit-text-fill-color: transparent` 做渐变金标题，此技术下 **`text-shadow` 不可见**（阴影画在透明填充下），且原 `font-weight: 800` 比 `--fw-title`(700)更饱满 → 该类**刻意不加 text-shadow、不降级字重**。
4. **emoji 必须包裹**：14 处标题以 emoji 开头（🗺️🏯🛡️🏮📜⚔️🎯🪙🎴）。emoji 走 Segoe UI Emoji 字体，会脱离 font-family 继承，与衬线中文并排时基线错位。解法：`.title-emoji` 降字号至 0.88em + `vertical-align: -0.04em` + `margin-right: 0.28em`。
