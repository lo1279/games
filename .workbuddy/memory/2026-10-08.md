## ⚠️ 关键教训：A–E 阶段做完，用户反馈"看起来没优化什么"

**根因**：内联 `style` 属性优先级 1000，**高于任何选择器**。index.html 有 214 处 inline style（font-size 114x / color 99x / padding 83x / display 68x / border-radius 33x），JS/main.js 里还有大量 `<button style=...>` 动态渲染按钮。所以 A–E 改的 CSS 令牌层被内联完全压制 —— **改的是 CSS，但真正决定外观的是内联**。仅改 CSS 无法产生可见变化。

**正确解法（阶段 G）**：不去删内联（风险高），而是**用 `!important` 属性选择器反向压制内联**，把视觉效果顶上来。追加在 style.css 末尾的「视觉精修层」：
- `.upgrade-btn[style*="颜色码"]` —— 按内联里的颜色值反推语义（绿=收益 / 金=主操作 / 红=消耗 / 紫=传承 / 蓝=试炼 / 灰=次要 / 半透明白=幽灵 / 金边半透明=查看），逐一接管 background/border/color。**必须先跑统计脚本列出 JS+HTML 里实际出现的全部颜色码**，不能凭猜（实测漏过 #065f46、#4b5563、#0284c7、#0369a1）。
- `.res-hud` / `.res-badge` —— 玻璃质感 + 金色描边 + hover 反馈。
- `.bottom-nav .nav-tab-btn::before` —— 选中态新增顶部金色指示条（transform scaleX 过渡）+ 图标上浮放大。
- `.upgrade-btn` 通用金属质感：inset 内高光 + 投影 + hover 上浮 1px + active 下沉。
- `#btnResetGame` —— 内联写死的高饱和红降为中性警示色。
- `.slg-tab-page h2` —— 加左金线（border-left 3px var(--border-gold)）+ 字号 18→20px + 行高 1.35。
- `input/select:focus` —— 补金色焦点环（内联覆盖了 outline）。
- `::-webkit-scrollbar` —— 改为暗金主题，原生滚动条过于刺眼。
- `@media (prefers-reduced-motion: reduce)` **放在视觉精修层之后**再补一段：否则前面的 `* { transition-duration: 0.01ms !important }` 会把视觉精修层的所有 hover 反馈抹平。减弱动效下保留颜色/阴影反馈但去掉位移。

**验证**：花括号 449/449 配平 ✅；变量无未定义 ✅；属性选择器覆盖 40 个 upgrade-btn 实例（含 JS 动态渲染）✅；本地 http.server 起 8899 返回 200 ✅。

## 🔴 视觉精修层回归修复：按钮文字看不见（用户反馈）

**两个 bug**：

1. **继承链断裂导致深字落深底**：JS 动态渲染的 `btn-change-hero`（更换）、`btn-add-hero`（+选拔名将上阵）、`btn-modal-change-tac1/2`（换配）等按钮**内联既无 background 也无 color**，原本靠外层继承文字色。精修层给 `.upgrade-btn` 加了 `border`（`border` 会打断某些继承链）却没有兜底文字色 → 深色字落在深色底上，完全不可见。
   **修复**：`.upgrade-btn` 显式兜底 `background: linear-gradient(180deg,#52525b,#3f3f46); color: #f4f4f5;`（7.03:1 AAA）。

2. **亮色背景配浅色字，对比度严重不足**（主因）。实测 7 项不达标：
   - 白字配 `#10b981` 绿 = **2.41:1**（AA 要求 4.5）
   - 白字配 `#f59e0b` 金 = **2.07:1**
   - 白字配 `#38bdf8` 蓝 = **2.01:1**

**补齐的色系**：`#1e3a8a`（深蓝·蜀国预设）、`#854d0e`（棕·蜀国预设）原先落到灰色兜底，语义色丢失。

**验证**：40 个 upgrade-btn → 33 命中色系规则，7 个走基础兜底（这 7 个内联确实无背景色，本就是次要/文字型按钮）；花括号 450/450 配平；11 项配色全部 ≥AA。

**⚠️ 教训**：做深色主题的视觉改造，**必须对每一组"前景色/背景色"组合跑 WCAG 对比度计算**，不能凭肉眼判断"深色背景配白字"。亮色按钮配白字是极易犯的低级错误，肉眼在暗底上看不出，但对比度只有 2:1。

## SLG 五星金光「路径 A」：纯 CSS 补短板（用户确认后执行）

**背景**：用户问「闪光效果怎么做到原版三国志战略版的品质」。查证开发商为广州灵犀互动，自研 3D 引擎 + 3D 粒子系统 + Shader + Bloom 后处理。原方案为 DOM/CSS 模拟，存在本质差距。给出三条路径 A(纯CSS补短板)/B(Canvas2D粒子)/C(WebGL Shader)，**用户选 A**。

**核心发现（关键坑）**：`mix-blend-mode` 在 `transform-style: preserve-3d` 容器内会失效（3D 上下文强制展平图层）。原代码把特效层放在 `.gacha-card-inner`（preserve-3d 的3D 翻转容器）内 —— 若只加一行 `screen` 完全无效，且横幅文字会被 rotateY(180°) 翻成镜像。
→ **解法：把特效层从 `.gacha-card-inner` 内移到 `.gacha-card-wrapper` 外层**。wrapper 有 perspective 但自身不参与翻转，且已设 `isolation: isolate`，是安全的混合上下文。

**改动清单**：
- `js/main.js`（抽卡卡牌构建）：`${fxHtml}` 从 `inner` 内移到外层；粒子 24 → 56 粒；新增 `--sway`（±23px 横向湍流摆动）与 `big` 类（每 4 粒掺 1 枚大亮片）；fxHtml 新增 `.gacha-bloom`。
- `css/style.css`：
  - 新增加色混合规则块：`.gacha-burst-ring/.gacha-flash-white/.gacha-bloom/.gacha-rays/.gacha-sparkle { mix-blend-mode: screen }`。**横幅刻意不加**（带文字实底块，screen 会让金底与文字互提亮糊掉）。
  - 新增伪泛光层 `.gacha-bloom`：460px 径向渐变 + `blur(12px)`，`:after` 再叠一圈 `blur(22px)` 外光晕，`bloomExpand` 关键帧。核心将时长 1.6s→2.5s。
  - 光柱 420→460px、色值提亮（0.55→0.75）、加 `blur(2.5px)` 柔化扇形边界（原版体积光无清晰边缘）。
  - 粒子：`sparkleFly` 改为 5 段轨迹（含 `--sway` 中段偏移模拟湍流），**新增正交的 `sparkleTwinkle` 亮度脉动动画**（CSS 无法在两动画间共享进度，故用独立短周期近似）；box-shadow 减弱。

## SLG 五星金光「路径 B」：Canvas 2D 粒子系统（用户确认路径 A 观感达标后执行）

**用户反馈**：路径 A「不错不错，有点那感觉了」→ 继续按方案 B 优化。

**新增文件 `three-kingdoms-slg/js/engine/goldfx.js`（约 380 行，零依赖单例 `goldFX`）**
实现原版三件CSS 做不到的事：
1. **真加色混合**：`globalCompositeOperation = 'lighter'`，粒子重叠处亮度累积（screen 只是近似）。
2. **廉价 Bloom**：粒子同时画入 1/4 降采样离屏 → `ctx.filter=blur()` → 放大画回主 canvas，等价"亮部向外溢出光晕"。替代真Bloom 的三级降采样。
   ⚠️ **踩坑**：初版用 `drawImage` 到自身做自模糊，虽有规范支持但部分移动端 WebView 内核会返回未模糊结果或抛错 → 改为**双离屏 ping-pong**（bloomCanvas 接收粒子 → bloomDst 承接模糊 → 放大画回主画布）。
   ⚠️ `ctx.filter` 低版本 Android WebView 不支持 → 特性检测，不支持时 `globalAlpha` 从 0.85 降到 0.42（仍有溢出感，边缘更硬）。
3. **逐帧物理**：重力 + 乘性阻力 + 二维值噪声湍流（`noise2` 用整数格点 sin + smoothstep 插值，非真Perlin）。亮度包络 `t<0.12? t/0.12 : (1-(t-0.12)/0.88)^1.6` —— 快速升起后缓衰减，比线性淡出更像火花。

**粒子规模**：普通五星 burst 96 粒 / 核心 150 粒；shockwave 30/46 粒（无重力、寿命短、纯横向扩散补冲击感）。池上限 260，超限直接丢弃新粒子而非无限增长。倒序 splice + swap-pop 回收。

**`js/main.js` 改动**：
- import `{ goldFX }`，`initDOM` 的 `closeGachaShowcase` 加 `goldFX.unmount()`（**必须**：否则 RAF 永久运行，移动端空转耗电发热）。
- `gachaShowcase.style.display='flex'` **之后**才 `goldFX.mount()` —— 顺序反了 rect 全 0，画布会是 1x1。
- 翻牌时 `requestAnimationFrame` 内 `goldFX.burst()`，坐标取 `wrapper.getBoundingClientRect()` 中心（视口坐标，画布与卡牌容器无定位关系）；**必须 rAF 推迟一帧**，否则读到翻转 transform 生效前的旧位置。
- 180ms 节点追加 `goldFX.shockwave()`。
- 重抽时 `goldFX.clear()` 清残留粒子。
- `goldfx.js` 内建 120ms 节流的 resize 监听（canvas 像素尺寸不随 CSS 自动变，旋转/缩放会拉伸变形）。

**`css/style.css`**：新增 `.gold-fx-canvas`（absolute inset:0, z-index:25, pointer-events:none，同级z-index 下压过卡牌且不参与 3D 翻转上下文）。
